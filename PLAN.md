# «Голос внутри» — план работ

## Контекст

Бабушка после инсульта: работает только левая рука, говорит 3–4 слова на казахском и русском, повторяет за другими, читать и писать, скорее всего, не может. Нужен офлайн-инструмент на планшете: она даёт обрывки (картинки, лица, место боли, свои слова, «да/нет»), собственный вероятностный движок угадывает мысль, уточняет вопросами и произносит фразу, которую она повторяет вслух. Второй пользователь — родственник под PIN: анкета жизни, словарь её слов, языки, история, прогресс речи.

Жёсткие рамки из ТЗ: никаких внешних ИИ и LLM, ноль сетевых запросов после первой загрузки, данные только в IndexedDB, от бабушки — только одиночные нажатия.

## Что уже решено

- **Счёт элементов на экране.** Постоянная панель слева внизу (Да, Нет, Помогите, Сначала, Сказать) не входит в лимит, всегда на одних местах и активна в любой момент. Рабочая область — не больше 6 плиток; больше 6 тем — вторая страница кнопкой «Ещё», без прокрутки.

## Конфликты скиллов с доступностью (приоритет у доступности)

1. `house-style`: «тёмная тема обязательна» и смена по системной настройке. Для бабушки внезапная смена вида плиток вечером ломает узнавание. Решение: режим пациента — одна фиксированная светлая спокойная тема; родственник может явно включить тёмную для пациента в настройках. Режим ухаживающего поддерживает тёмную тему по системе.
2. `house-style` в блок-листе называет «одинаковые карточки с одним радиусом». Для неё одинаковая форма плиток — это предсказуемость, а не шаблонность. Плитки остаются одинаковыми; характер дизайна строю на цвете, шрифте и экране итоговой фразы.
3. `house-style`: «документы — HTML по умолчанию». README по ТЗ на русском в Markdown — следую ТЗ (не конфликт доступности, просто фиксирую).

## Движок вывода (ядро)

- **Кандидат** = фрейм + заполненные слоты. Около 40 фреймов в `frames.json`, добавление фрейма — правка данных без кода.
- **Оценка:** `log P(c) = log prior(frame | время суток) + Σ log P(свидетельство | c)`, нормировка по лучу. В распределение добавлен псевдокандидат «ничего из этого» с фиксированной массой, чтобы закрытый мир не завышал уверенность.
- **Лучевой поиск:** сначала оцениваются фреймы, берутся лучшие K=12, затем раскрываются слоты по оценкам сущностей, луч B=200.
- **Свидетельства** (таблицы в `likelihoods.json`): тема, лицо, зона тела + сила, фото, слово (значения из словаря, смешивание с равномерным по уверенности распознавания: `c·L + (1−c)·U`), время суток, заметки дня (буст связанных сущностей до истечения срока), ответы.
- **Повторы:** одинаковые слова в пределах 3 с → одно свидетельство, отношение правдоподобия в степени 1.25; при отметке «часто повторяет» степень 1. Число серий пишется в историю.
- **Шум ответов:** `P(да | утверждение верно) = 1−ε`, ε стартово 0.1, обновляется по истории (бета-счётчик). Один неверный ответ стоит ≈ −2.2 нат и восстановим. «Почти» = тема верна, гипотеза целиком нет.
- **Выбор вопроса:** по всем вопросам о теме, слоте и целой гипотезе считается ожидаемое снижение энтропии с учётом ε; уже заданный вопрос не повторяется.
- **Остановка:** лучший кандидат > 0.75 → полная фраза и «Так?». После 6 вопросов без порога — сетка из 4 лучших гипотез картинками; «Нет» на всех = отрицательное свидетельство для всех четырёх, поиск продолжается.
- **Обучение:** после подтверждения — +1 в счётчики Дирихле (фрейм × время суток, частоты сущностей, значения произнесённых слов); отклонённая финальная фраза — дробное отрицательное обновление с нижней границей. Счётчики хранятся в Dexie, движок получает их на вход и возвращает новые (чистые функции).
- **Составные сообщения:** после «Да» на фразу — «Ещё что-то?», затем 5 плиток связок (потому что / но / поэтому / и / потом) и «Всё». Сущности из предыдущих предложений получают буст априора.
- **«Почему так»:** движок возвращает для каждого кандидата список вкладов свидетельств (источник, лог-вес) — это и есть экран объяснения.

## Генерация фраз и морфология

- Шаблоны в одном файле на язык: `Я хочу увидеть {person:acc}`, `{g:рад|рада}` для рода говорящего, `{q}` для казахской вопросительной частицы, согласуемой с предыдущим словом. Ручные формы от родственника хранятся как переопределения и имеют приоритет над правилами.
- **ru-morph:** женские на -а/-я и -ия (Алия → Алию, Алии, с Алией), мужские на согласный (Ерлан → Ерлана), женские на согласный несклоняемы (Гульнар), на -ь — по настройке (Айгуль → Айгули или несклоняемое); лексикон существительных с родом, одушевлённостью и типом склонения; согласование глаголов и прилагательных с родом говорящего.
- **kk-morph:** сингармонизм по последнему гласному (твёрдый/мягкий ряд, ә ө ү ұ і, заимствования), группы конечного звука для выбора н/д/т и ғ/г/қ/к, озвончение к/қ/п на стыке (кітап → кітабы), шесть падежей, притяжательные, множественное, ма/ме/ба/бе/па/пе.
- Тесты на всех именах и словах из ТЗ в обеих записях (Алия/Әлия, Нурлан/Нұрлан и т. д.). В `TODO.md`: казахские шаблоны и формы проверить носителю; экран проверки шаблонов в режиме ухаживающего.

## Звук

- **Порядок источников:** запись голосом родственника → локальный синтез → склейка записанных фрагментов. Режимы звучания (ru, ru+kk, kk+ru, kk) резолвятся по цепочке «элемент → категория → глобально»; отмеченные слова для развития всегда двуязычные.
- **Синтез — исследование переношу в конец фазы 1** (см. «Слабые места»). Кандидаты: голоса Piper `ru_RU` и `kk_KZ` в браузере через onnxruntime-web. Известные риски: размер моделей (десятки мегабайт на голос), фонемизатор espeak-ng под GPL-3.0, качество казахских голосов, лицензии наборов данных отдельных голосов. Покажу таблицу: 5 тестовых фраз на язык (аудиофайлы вам), размер, лицензия, скорость. Скорость на настоящем планшете я измерить не могу — замерю в контейнере и добавлю в режим ухаживающего экран замера, который покажет время на вашем планшете.
- **Распознавание:** захват через Web Audio (AudioWorklet), VAD по энергии с порогом от шума, 16 кГц моно; MFCC + CMVN; DTW против её образцов; kNN → топ совпадений с уверенностью; серия одинаковых слов → одно слово с пометкой. Низкая уверенность → «Вы сказали „сен“?». Нераспознанные попытки — в историю.
- **Проверка точности 85 %:** экран теста распознавания считает точность перекрёстной проверкой с исключением по одной записи на её собственных образцах. В CI — прокси-набор (синтезированные слова с аугментацией скорости, высоты и шума), он проверяет конвейер, а не её речь. Честно: на речи с афазией цифра может отличаться, реальную покажет экран.

## Интерфейс пациента

- Альбомная 1180×820: слева колонка панели (Помогите вверху, Сначала и Сказать посередине, Да и Нет внизу), справа сетка 3×2. Портретная 820×1180: Помогите и Сначала сверху, сетка 2×3, внизу слева Да, Нет, Сказать. Телефон: сетка 2×2 + «Ещё». Правая рука — зеркально.
- Плитки ≥ 120×120, промежутки ≥ 24 px, сначала картинка и звук, подпись мелкая.
- Обработчик нажатий: срабатывание на `pointerup`, отсечение < 60 мс, глобальная пауза 800 мс, отказ при втором активном указателе и при большой площади контакта (`width × height`, где браузер её даёт). `touch-action: none`, без зума и прокрутки; e2e проверяет отсутствие прокрутки на всех вьюпортах.
- Экраны: темы → подэкраны (лица, тело спереди/сзади → сила боли, фото людей/мест/вещей/еды/лекарств, фреймы темы), вопрос (картинка + голос + Да/Нет/Почти), «Так?», итоговая фраза крупно для собеседника + «Повторите» + «Ещё по-казахски», «Ещё что-то?», сетка 4 гипотез.
- Wake lock (при поддержке браузером), вход в режим ухаживающего — удержание невидимого угла 3 с → PIN.
- Отметку «сама / с подсказкой / не смогла» родственник ставит в истории и в режиме развития речи, а не мелкими кнопками на экране бабушки.

## Слабые места первого варианта и что я поменял

1. **Симулятор проверяет движок его же моделью** — метрики будут завышены. Поменял: у виртуальной бабушки отдельная поведенческая модель с расхождениями (ошибочные темы с вероятностью 0.15, ε выше, чем думает движок, повторы, слова с неожиданным значением). Отчитываюсь по обоим режимам: «согласованный» и «с расхождением». Целевые цифры (≤ 5 шагов в среднем, 90 % правильных) проверяю на втором.
2. **«Шаг» не определён.** Фиксирую: шаг = любое действие бабушки (нажатие, слово, ответ). Подтверждение «Так?» тоже шаг.
3. **Выбор синтеза в фазе 4 слишком поздно** — от него зависят размер кэша, service worker и цепочка озвучки. Перенёс исследование и сравнение в конец фазы 1; пока вы выбираете, иду по фазам 2–3.
4. **Модели синтеза на десятки мегабайт и iOS-квоты.** Оболочка приложения кэшируется при установке, голоса — в отдельный кэш с прогрессом; вызываю `navigator.storage.persist()`; индикатор офлайн-готовности. Резервная копия на случай очистки хранилища Safari.
5. **Понимание речи у бабушки не проверено**, а весь цикл держится на «да/нет». Смягчение: ε учится по её истории, родственник может задать его вручную, сетка картинок срабатывает раньше при высоком ε. Диагностику не добавляю — это за рамками ТЗ.
6. **Распознавание её речи может не дотянуть до 85 %.** Приложение полностью работает без микрофона; переспрос при низкой уверенности; цифра проверяется на её записях экраном теста.
7. **Площадь касания на iPad браузер часто не отдаёт.** Отсечение ладони работает там, где есть данные; мультитач и пауза 800 мс работают везде. Ограничение записываю в `DECISIONS.md`.
8. **Статический экспорт и динамические маршруты** — разделы через query-параметры, без `generateStaticParams`.
9. **Автовоспроизведение звука** — первый звук после первого нажатия; на заставке одна большая плитка «Начать».
10. **Объём казахской грамматики и шаблонов** — правила + ручные переопределения + экран проверки носителем; без претензии на полноту.
11. **Лишнее:** отказался от Meyda и next-pwa (свой MFCC и свой генератор списка предкэша проще проверить тестом офлайна).

## Проверка

- `npm run check`: `tsc --noEmit` (strict) + Vitest (движок, морфология обоих языков, ASR на синтетике, схема данных, импорт/экспорт туда-обратно).
- `npm run sim`: средний и максимальный путь, доля правильных фраз, оба режима симулятора, 1000 прогонов с фиксированным seed.
- Playwright: полный путь бабушки только нажатиями от первой плитки до произнесённой фразы на трёх вьюпортах; отсутствие прокрутки; размеры и промежутки целей; режимы звучания (перехват очереди воспроизведения); вход в режим ухаживающего удержанием угла.
- Офлайн: загрузка, `context.setOffline(true)`, перезагрузка, полный путь; все запросы после первой загрузки обслужены service worker'ом, ни одного запроса на чужой origin.
- Отсутствие внешних ИИ: проверка зависимостей и исходников на запрещённые домены и пакеты в CI-скрипте.
